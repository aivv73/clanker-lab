# Disclose stale language profiles without hiding them

A cached source-language profile belongs to one analysis target, while provider attempts are recorded per installed package version. After an upgrade, the installed version may resolve to a new target (or to nothing) while the database still holds an analyzed profile attached to the older version's target. Paclang reports that package as stale analysis: the old profile stays included in the analyzed share by default, and `coverage.stale` discloses how much of the analyzed share is stale. A definitive `no_language` profile on the current target suppresses older profiles, so a stale language never overrides a known-empty current source; a failed or absent current analysis falls back to the older profile as stale. Adapter and input mismatches are not judged offline: every sources-only refresh with a configured Linguist adapter re-analyzes its acquired targets and overwrites their profiles, so input staleness heals on refresh and reports only disclose version staleness.
