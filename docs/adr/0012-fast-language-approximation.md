# Add a fast language-analysis provider with explicit fidelity

Downloading every packaged source before analysis is the honest default, but it turns a quick language question into a full acquisition run. Paclang gains a fast provider that reads byte counts from a GitHub-compatible Languages API (`{api-root}/repos/{owner}/{repo}/languages`) without downloading anything. The endpoint always describes upstream HEAD, never the packaged revision, so fast profiles carry `current-upstream` fidelity and reports count them as approximations, never as exact analysis: a separate coverage share, excluded from `--min-coverage`, with `source` and `fidelity` on every stored profile.

Three refresh policies select the trade-off explicitly (`--analysis-mode`, default `exact`): `fast` never acquires and approximates GitHub-hosted targets only; `exact` always acquires packaged revisions and analyzes them locally; `auto` reuses stored exact profiles, approximates GitHub-hosted gaps, and acquires plus analyzes the rest. An approximation never overwrites an exact profile, in any mode. Adapter and input mismatches need no offline judgment: exact refreshes overwrite approximations, and fast refreshes skip exact evidence, so each mode converges on its own evidence without mixing.
