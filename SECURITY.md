# Security and reliability context

Paclang is a synchronous, non-interactive CLI run with the invoking user's permissions on an ALPM system. It must not request root privileges. The executable reads `XDG_DATA_HOME` and `HOME`, creates and opens its SQLite analysis database, and writes reports to standard output. Metadata refresh invokes `pacman -Qq` and `expac -Q` to read local package state. Paclang does not access the network, send telemetry, modify packages, or handle secrets.

Environment variables, process output, and an existing database are external inputs. Paclang accepts only absolute XDG or home paths. Metadata refresh validates the complete `pacman` and `expac` populations before publishing a snapshot. Paclang validates the SQLite schema version before application queries and refuses databases created by newer unsupported versions without modifying them.

Package-origin filter values must be nonempty and cannot contain control characters. Structured reports encode origins as strings. Terminal and Markdown reports render selected origins as a quoted string list so commas, quotes, and the literal origin `all` remain distinct from filter syntax.

The `%r` field from `expac -Q` identifies the queried local database, not the repository that installed a package. Paclang does not load libalpm or parse its local database directly. Paclang records package origin as unknown and does not infer historical origin from current repository state.

Schema version 1 could record only an inventory snapshot marker, not package rows. Migration 2 removes version-1 marker rows in the same transaction that adds installed-package storage, so reports cannot treat an old marker as a valid empty inventory.

Concurrent CLI invocations are expected. Schema migration and refresh acquire SQLite's write lock before checking or changing schema state. Refresh holds the single-writer transaction through inventory capture and publication. Reports hold a shared sidecar snapshot lock through their SQLite read transaction and report construction. Refresh takes the same lock exclusively after the SQLite writer lock and before retention, then holds both through commit. This lock order lets reports read the previous snapshot during capture but prevents retention from running during a report read. Report and refresh block on the sidecar lock until acquisition or SIGINT; the try-lock plus sleep exists so SIGINT stays prompt instead of blocking in `flock`. Migrations and publication remain transactional so interruption or failure cannot expose partial state. A capture matching either boundary fingerprint is coherent; matching only the earlier sample publishes a stale snapshot, and matching after a change-then-revert is accepted as current rather than retried.

Invalid CLI syntax exits 2. Runtime and output failures exit 1 without panicking. An interrupted refresh terminates its active inventory subprocess, rolls back the refresh transaction, and exits 130. The interrupt handler disarms the tracked process group as soon as the child is reaped, but a SIGINT landing in that narrow window can SIGKILL an unrelated process if the OS has already reused the PID; this residual risk is accepted while inventory capture stays single-threaded on Linux and must be revisited before threaded capture or non-Linux ports. Structured runtime errors go to stdout in the selected format. Stderr is reserved for diagnostics.

`PRAGMA user_version` identifies the persisted schema version. Changes to migrations or persisted tables must add compatibility tests for empty, current, malformed, and newer-version databases. Storage tests must also cover concurrent first use. CLI tests must cover XDG fallback, isolated data directories, output content, and exit status.

The current database contains no secrets. Another process running as the same user can alter it, and Paclang does not defend against that user-level compromise. Revisit file permissions and tamper resistance before storing credentials, private-source metadata, or data written by a privileged process.
