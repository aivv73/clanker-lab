# Paclang

Paclang analyzes the programming languages behind packages installed on an ALPM system.

The executable stores its SQLite analysis database at `$XDG_DATA_HOME/paclang/paclang.db`. If `XDG_DATA_HOME` is unset or is not an absolute path, Paclang uses `$HOME/.local/share/paclang/paclang.db`.

Run `paclang refresh --metadata-only` to read installed package metadata from `pacman` and `expac` and publish an inventory snapshot. Paclang checks the captured names and versions against lightweight samples taken around the metadata read. A package change may make the new coherent snapshot stale; metadata that matches neither sample is rejected as mixed. Failure or interruption leaves the previous snapshot active, and interruption exits 130. Paclang retains the latest ten published snapshots.

Run `paclang refresh --recipes-only` to capture inventory and fetch Arch `.SRCINFO` metadata for the selected packages. This mode records source-provider evidence; it does not download source trees or run Linguist, so analysis coverage remains missing. Package-base/version groups share one request. Missing recipes, network failures, mismatched versions, dynamic or unpinned sources, architecture-specific source arrays, and unclear primary sources are recorded as unresolved. Matching pinned HTTPS Git sources or versioned HTTPS archives receive reconstructed evidence because package origin remains unknown. Recipe commits and attempt timestamps are stored for provenance and freshness. A final inventory sample marks the snapshot stale if packages changed during fetching.

Arch recipe requests use the installed version's Arch packaging tag and never fall back to the current branch. They run with at most 8 concurrent connections, limited to 20 seconds and 2 MiB per API response, with a 1 MiB decoded `.SRCINFO` limit. Members with an already-resolved or source-free attempt reuse the stored evidence without refetching; unresolved attempts are retried. When standard error is a terminal, recipe fetching shows a live progress block with completed groups, downloaded bytes, resolved and unresolved counts, elapsed time, and ETA; piped output stays silent so structured reports on standard output are unaffected. SIGINT cancels the request and rolls back all attempts from that refresh along with publication. Successful partial refreshes publish normally. `--metadata-only` remains offline. `--explicit`, `--dependency`, and `--origin` limit recipe fetching and report selection; the complete inventory is still published.

The default recipe endpoint is `https://gitlab.archlinux.org/api/v4`. `--arch-api-url` selects a trusted Arch-compatible GitLab API with `--recipes-only` or `--sources-only`; HTTPS is required except for literal loopback HTTP addresses used by local fixtures. Redirects and URL credentials are not used. Proxy environment variables are never read; `--proxy-url` selects one explicit HTTPS proxy (loopback HTTP for fixtures) for recipe, archive, and Git requests when direct egress is unavailable. Building the HTTP adapter requires libcurl development files; recipe fetching requires an asynchronous-DNS libcurl build. Language analysis remains a future slice.

On CachyOS, add `--cachyos` to `--recipes-only` or `--sources-only`. After Arch resolution, the `cachyos` provider tries remaining selected packages against [CachyOS-PKGBUILDS](https://github.com/CachyOS/CachyOS-PKGBUILDS). It pins the current `master` commit, reads its complete tree once, and fetches existing `.SRCINFO` blobs by object ID. Matching versions receive `reconstructed` evidence. A single extra numeric package-release suffix (for example `1:7.2.7-1.1` versus `1:7.2.7-1`) may match with grade `fallback`; epoch, upstream version, package base, and split-package membership must still match. When no custom package directory exists, that same rebuild mapping can try the corresponding Arch packaging tag. A custom directory without usable `.SRCINFO`, a stale recipe, or a truncated/failed repository index stays unresolved. Fallback evidence identifies a candidate upstream source, not the exact CachyOS build or its patches. Historical CachyOS recipes, separate recipe repositories, and AUR lookup are not covered.

```sh
paclang refresh --sources-only --cachyos --explicit --proxy-url http://127.0.0.1:2080
```

`--cachyos-api-url` overrides the GitHub-compatible repository API root (default `https://api.github.com/repos/CachyOS/CachyOS-PKGBUILDS`) and requires `--cachyos`. The same transport limits, explicit proxy, cancellation, and transaction rules apply. GitHub API rate limits and missing metadata remain visible as unresolved attempts; no authentication is used. Already-resolved candidates are reused, including on subsequent CachyOS refreshes.

A matching recipe with no declared sources is recorded as `source_free` (for example, metapackages such as `base` and `base-devel`, or generated packages). This requires a valid recipe and exact package base, member, and version match; local source files, architecture-specific sources, malformed metadata, and ambiguous source lists are not treated as source-free. No source target is invented. Acquisition is `not required`, CachyOS fallback is skipped, and the result is cached. These packages do not fail `--require-complete` and are excluded from the language-analysis denominator: `coverage.source_free_packages` reports the excluded count, while installed and selected totals remain unchanged. An all-source-free selection has a zero denominator and satisfies `--min-coverage`. A concrete resolved source from another provider takes precedence over a source-free claim.

Run `paclang refresh --sources-only` to resolve recipes, download each distinct selected source target, verify it, and materialize a temporary Git worktree. The stage records acquisition outcomes and deletes downloads and worktrees when finished. Without `--linguist-executable` it does not run Linguist and language-analysis coverage remains missing. With a configured native `github-linguist` executable (or `PACLANG_LINGUIST_EXECUTABLE`), each acquired worktree is analyzed with `<executable> --json` before cleanup and its source-language profile is stored; `count` then reports analyzed coverage and `--min-coverage` gates on it. `paclang providers` shows the latest acquisition state, failure reason, byte and entry counts, verified Git commit, and archive SHA-256 alongside the original provider evidence, plus the stored analysis state, source, fidelity, and primary language. The refresh report includes a `source_acquisition` summary. Incomplete targets normally publish as partial data; add `--require-complete` to exit 1 after publication if acquisition failed, hit a limit, or any selected package lacks a resolved source.

`--analysis-mode` selects the language-analysis policy (default `exact`): `fast` downloads nothing and approximates GitHub-hosted targets through the Languages API at `--github-api-url` (default `https://api.github.com`, loopback HTTP allowed for fixtures; no authentication is used); `auto` reuses stored exact profiles, approximates GitHub-hosted gaps through the API, and acquires plus analyzes everything else. The first throttled API response trips a circuit breaker that skips every unfired request without recording it, so a later refresh retries instead of fossilizing failures. Set `PACLANG_GITHUB_TOKEN` to authenticate API requests (environment only, never a flag); blank or malformed values fail safe to no authentication and the token never reaches logs or the database. Same-host API redirects from renamed repositories are followed up to three hops; anything leaving the API host is recorded as a failure. Recipe fetching never follows redirects or authenticates. Fast profiles describe upstream HEAD rather than the packaged revision, so reports count them as `approximate` evidence apart from exact analysis: a separate coverage share and row, excluded from `--min-coverage`, with per-package source (`linguist` or `github-api`) and revision fidelity (`exact-packaged-source` or `current-upstream`) in `providers`. An approximation never overwrites an exact profile.

Archive verification requires a positional `sha256sums` or `sha512sums` value from `.SRCINFO`; SHA-512 takes precedence when both exist. Missing checksums, `SKIP`, and unsupported checksum algorithms cannot establish verification and produce a failed acquisition. Sources-only refresh refetches previously resolved archives that lack this evidence. Checksums are checked before extraction, and successful downloads also record their SHA-256. Supported containers are tar and ZIP, with built-in gzip, bzip2, xz, zstd, and lzip decoding. Archive wrapper directories are removed when there is exactly one top-level directory. Unsafe paths, embedded `.git` directories, hard links, special files, and symlinks containing parent traversal are rejected rather than producing an incomplete tree.

Git acquisition fetches only the named tag or full SHA-1 commit, verifies fetched object hashes, records the peeled commit, and creates a fresh repository from that tree. An unavailable revision never falls back to the default branch. SHA-256 Git repositories and submodules are currently unsupported. Verification establishes content integrity and the recipe's selected revision; it does not verify upstream signatures or make mutable tags immutable. Both acquisition paths avoid executing source code, PKGBUILDs, hooks, or checkout filters. Source URLs require HTTPS without credentials, with literal-loopback HTTP allowed for fixtures. Archives may follow up to five validated redirects without HTTPS downgrades; Git redirects are refused.

ADR 0008 defaults apply to each target: four concurrent workers, 1 GiB downloaded, 4 GiB expanded, 250,000 source entries, and a 900-second wall deadline covering download, verification, extraction, and Git materialization. Entry accounting includes directories and symlinks; Git also checks expanded fetched-object sizes. The parent process kills and reaps timed-out or interrupted workers before removing their temporary directories under `$XDG_CACHE_HOME/paclang/sources` (or `$HOME/.cache/paclang/sources`). SIGINT rolls acquisition records back with the refresh and preserves the previous snapshot. A forced process termination can leave disposable cache directories. Successful acquisition records describe the last run; trees are disposable, so another sources-only refresh reacquires them.

Override these limits with `--source-jobs`, `--max-download-bytes`, `--max-extracted-bytes`, `--max-source-files`, and `--source-timeout-seconds`, or configure defaults through `PACLANG_SOURCE_JOBS`, `PACLANG_MAX_DOWNLOAD_BYTES`, `PACLANG_MAX_EXTRACTED_BYTES`, `PACLANG_MAX_SOURCE_FILES`, and `PACLANG_SOURCE_TIMEOUT_SECONDS`. Explicit flags override environment configuration. Source acquisition additionally requires libarchive development files at build time; its decoders must be built in. Git transport uses libgit2 through the Rust binding, and integration fixtures require the Git executable.

Run `paclang count` to report the installed total, the selected population, and missing source-language analysis from the latest published snapshot. The report compares the snapshot with `pacman -Q` and marks it `current` or `stale`. Snapshots created by an older database version report `unknown` until the next refresh. Before the first refresh, the report returns `no_snapshot` and suggests the refresh command. A package whose installed version no longer has its own analyzed profile, but has one from an older version's source target, counts as analyzed with a separately disclosed `stale` contribution (`coverage.stale`, plus a human `Stale analysis (included in Analyzed)` row); a definitive empty-language result on the current source suppresses older profiles instead.

Run `paclang providers` to inspect stored provider attempts for each selected package version in the latest snapshot, or `paclang providers --format json` for automation. The report includes targets, evidence grades, failure reasons, and recipe locations and commits; absent provenance is explicit. Packages sort by name and attempts by provider. Package totals partition the selection into `resolved` (at least one resolved candidate), `source_free` (no resolved target but a matching source-free recipe), `unresolved` (attempts exist but none resolved or source-free), and `not_attempted`; every candidate remains visible without choosing a provider winner. Attempts for older package versions are excluded. Inventory and attempts are read in one transaction, and snapshot staleness is checked like `count`. When the installed version lacks its own analyzed profile but an older version's profile exists, the package is flagged `stale` so the carried-over language evidence stays visible. This command does not fetch recipes; rerun `refresh --recipes-only` to retry stored failures after resolver changes. Provider resolution does not count as language-analysis coverage for `--min-coverage`.

Use `--explicit` or `--dependency` to select one install reason. Repeat `--origin <name>` to select the union of named package origins. Repeat `--package <name>` to select only those installed packages by name, which also limits recipe fetching and source acquisition to the selection. You can combine an install-reason filter with origin filters. An origin that is not in the snapshot selects zero packages. The current metadata refresh records every package origin as `unknown`, so `--origin unknown` is the only origin that can select packages from a snapshot created by this version.

## Report formats and stability

One typed report model feeds all four formats: `terminal`, `toon`, `json`, and `markdown`. Format selection never changes the reported facts. A TTY selects `terminal`, redirected stdout selects `toon`, and an explicit `--format` always wins.

JSON is the durable interchange contract for automation: working-draft TOON changes never break it. Every structured success and error carries `schema_version` (currently `1.5.0`); reject output whose schema version you do not understand. TOON output additionally declares `toon_specification_version` (currently `3.0`, the working-draft TOON specification the serializer targets).

Structured output carries integer numerators and denominators, so agents and scripts can compute exact shares. Human output shows percentages rounded deterministically to one decimal place; the coverage rows total 100.0% for any nonzero coverage denominator (an empty selection reports 0.0% rows). Coverage rows sort by count descending and state name ascending, and their counts always sum to the coverage denominator.

Pass `--min-coverage <percent>` (0 to 100) to make a report fail when analyzed coverage is below the threshold. The report facts are unchanged; only the exit status becomes 1. An empty selection is vacuously complete and always satisfies the threshold.

Recipe API HTTP 429 responses are retried at most three times per request. Retries honor `Retry-After` seconds or HTTP dates; missing or invalid values use 1, 2, and 4 second backoff. Only throttled requests are retried, preserving successful results. A requested delay above 60 seconds leaves the request unresolved instead of retrying early. Retry waits check cancellation every 50 ms.

List installed packages by any stored language name (case-insensitive; quote names containing spaces):

```sh
paclang packages rust                  # primary language is Rust
paclang packages rust --contains       # Rust bytes > 0
paclang packages rust --min-share 0.5  # Rust source-byte share >= 50%
paclang packages 'C++' --fidelity best-available
```

The default `--fidelity exact` uses exact packaged-source profiles, including explicitly marked stale cached fallbacks. `best-available` prefers exact profiles and otherwise uses current-upstream approximations, labeled on each result. Distinct source targets are counted once per package; their language bytes determine the primary language and shares (ties use language-name order). `--contains` and `--min-share` are mutually exclusive. Shares range from 0 to 1; zero includes absent languages in nonempty profiles, while empty or missing profiles never match. Unknown language names normally yield an empty result. Population filters, all report formats, and the exact-analysis `--min-coverage` gate also apply.

Use `paclang packages rust --sort share` to list the highest Rust shares first, or `--sort bytes` for the largest Rust byte counts first. Both break ties by package name and work with every matching mode and output format. The default is `--sort name`.

`paclang riir` presents **Rewrite It In Rust** progress, with a progress bar, Rust/C/C++/Other source bytes, package-analysis coverage, and the top three rewrite candidates ranked by descending C/C++ bytes (ties by name). Its oxidation ratio is **Rust / (Rust + C + C++)**; remaining bytes are **C + C++**. Other languages are outside this denominator. Global totals reuse `source-bytes` and count shared targets once; candidate shares describe each package separately.

```sh
paclang riir
paclang riir --bar crabs
paclang riir --fidelity best-available
paclang riir --format json
```

The command defaults to human output even when redirected; use `--format json|toon` for structured data without memes. Human output always ends with `The crabs demand … more.`, preceded by a message for the current oxidation stage. `--bar blocks` is the default; `--bar crabs` assumes two-cell emoji rendering and `--bar ascii` uses an ASCII bar. Byte sizes use binary units.

`--fidelity exact|best-available`, population filters, and `--min-coverage` follow the other reports. Stale evidence and fidelity remain disclosed. JSON includes `oxidation_ratio`, `riir_remaining_ratio`, integer byte counts, candidates, and the underlying source-analysis report. Both ratios are `null` when no Rust/C/C++ bytes were measured. Unknown source-byte volume is unmeasurable from missing profiles (`unknown_source_bytes: null`), rather than inferred from installed package sizes. Coverage is package coverage, not byte coverage. In `best-available` mode the headline combines exact analysis and approximate fallbacks, with each contribution shown separately; in `exact` mode it shows only exact coverage. JSON `coverage_ratio` follows the selected fidelity, with `exact_coverage_ratio` and `approximate_fallback_coverage_ratio` disclosing its parts. Stale exact evidence remains included, and `--min-coverage` still gates on exact coverage. Human output labels Other as excluded from the oxidation denominator and shows candidate bytes first, with share as a secondary indicator.

`paclang clanker-index` applies the explicitly subjective **clanker-language-tierlist-v1** policy to the existing measured source-language bytes. It reuses `source-bytes` selection, shared-target deduplication, exact/approximate preference, and disclosed stale fallbacks, with no acquisition or network calls.

```sh
paclang clanker-index
paclang clanker-index --fidelity best-available
paclang clanker-index --top 5
paclang clanker-index --all
paclang clanker-index --format json
```

The frozen v1 policy is the accepted [editorial tierlist](clanker-index-tierlist.md). Its ordinal weights are S+=6, S=5, A=4, B=3, C=2, D=1, F=0. The internal byte-weighted mean uses only **gradeable programming bytes** and maps to the nearest tier, with exact half-way values rounded toward the higher tier. No numeric score is displayed. Empty, ancillary-only, and entirely unjudged populations have no grade (`grade: null`).

A pinned offline snapshot of the supplied Linguist registry determines language type and group. The report separates **gradeable programming bytes**, **ungraded programming bytes (???)**, and **ancillary bytes** (markup, prose, data). HTML/CSS/MDX/Roff are ancillary; Perl and Prolog remain unjudged programming languages. Ancillary bytes never affect the grade or appear before the Clanker Council. Names absent from the registry are separately disclosed as `unknown_type_bytes`, excluded from grading without guessing their type. Synthetic Bend 2/Psi retain explicit project-local programming status and count only when measured.

Exact policy overrides win over registry parent/group inheritance, including explicit `???` decisions. Identical parent tiers use inheritance for Python console, Snakemake, Lean 4, Literate Agda/Haskell, Julia REPL, TSX, and other registry variants. fish, Tcsh, Java Server Pages, and JavaScript+ERB retain their individual tiers. Child languages keep their own emoji and verdict even when the tier is inherited.

Policy semantics (`src/report/data/clanker-language-tierlist-v1.json`) and terminal presentation (`src/report/data/clanker-presentation.json`) are separate. Changing a joke does not change grading. The registry type/group snapshot is pinned with its source SHA-256; a future change to v1 tier or applicability semantics needs a new policy version, rather than silent rebalancing. Presentation edits may evolve independently.

Human output shows emoji, verdicts, a system-grade joke, the top ten programming languages, and at most three unjudged-language details. `--all` shows the entire programming breakdown; `--top N` limits its displayed rows. Hidden programming bytes form an explicitly display-only mixed-tier remainder. Language percentages use **all measured source bytes** as their denominator, including ancillary bytes. This command defaults to human output even when redirected.

Clanker Index JSON/TOON use report schema **2.0.0**, independently of other reports. They contain no presentation fields or grade jokes. `languages` contains all programming rows; `ancillary_languages` and `unknown_type_languages` preserve the other measured rows. `ungraded_programming_bytes` replaces the old catch-all `ungraded_bytes`; `ancillary_bytes` and `unknown_type_bytes` disclose the exclusions separately. All four byte buckets sum to `total_source_bytes`. The complete original `source_analysis`, registry identity, inherited tiers, and coverage components remain available regardless of terminal trimming.

Coverage is still package-analysis coverage. Best-available shows exact plus approximate fallback; `--min-coverage` still gates on exact coverage. Fidelity, snapshot staleness, and stale bytes included in the report remain explicit. Acquisition, target deduplication, stored measurements, and the other reports are unchanged.
