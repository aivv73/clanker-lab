# ARCH-clanker-lab: Repository architecture

Clanker Lab contains the Paclang Rust package and project-level agent instructions.

The `paclang` executable owns command parsing and output-format selection. Its report model renders the same facts as terminal, TOON, JSON, and Markdown output. The storage boundary owns the SQLite analysis database under the XDG user data directory. Subprocess tests exercise the compiled executable with isolated user directories.

`paclang refresh --metadata-only` holds SQLite's single-writer transaction while it reads the installed package population from `pacman` and `expac`. The inventory boundary compares name-and-version fingerprints around metadata capture. A capture matching either boundary sample is coherent; a later package change can make that snapshot stale. Metadata matching neither sample is rejected as mixed. The storage boundary publishes and prunes snapshots in the same transaction. The inventory boundary records package origin as unknown when local package metadata has no authoritative origin and never substitutes current repository matches.

`paclang refresh --recipes-only` extends inventory capture with an Arch source provider with bounded concurrent fetching. The provider groups selected installed packages by package base and version, fetches `.SRCINFO` from the corresponding packaging tag through a bounded HTTP boundary (up to eight requests in flight, in batches of 32 groups), validates package identity and version, and records reconstructed source evidence or an unresolved outcome. Recipe commits identify the metadata used; attempt timestamps record freshness. Already-resolved attempts reuse stored evidence; unresolved attempts are retried. Terminal stderr shows group progress, downloaded bytes, resolved/unresolved counts, elapsed time, and ETA; redirected stderr stays silent. This recipes-only stage records source targets without fetching their contents or producing language profiles. Local recipe files and remote signatures, `.patch`, and `.diff` files are auxiliary inputs, excluded from primary-tree selection; exactly one supported archive or pinned Git tree is still required. Provider failures are data; interruption or publication failure rolls attempts back with the refresh transaction. A final inventory fingerprint sample detects changes during recipe fetching. Package origin remains unknown regardless of recipe matches.

`paclang refresh --sources-only` extends the recipe stage with source acquisition. Positional SHA-256/SHA-512/BLAKE2 recipe checksums persist with provider evidence; legacy resolved archives without checksums are refreshed before acquisition. Distinct targets, including their checksum evidence, share acquisition work across selected packages. A parent supervisor launches bounded worker processes and owns their cache-backed temporary directories, hard wall deadlines, cancellation, and cleanup. Workers download bounded archives, verify checksums before decoding through libarchive, validate paths and entry types, enforce expanded-byte and entry limits, and initialize clean Git repositories without filters or hooks. Git workers fetch a pinned tag or commit, verify object identities and expansion sizes, materialize the tree without submodule recursion, and build an isolated repository. A materialized-source handle supplies the disposable worktree to the next pipeline stage before cleanup. Language analysis remains separate.

Acquisition defaults follow ADR 0008: four concurrent targets, 1 GiB downloaded, 4 GiB expanded, 250,000 entries, and 15 minutes per worker, configurable through explicit refresh flags and environment settings. Storage migration 6 adds checksum evidence and per-target/checksum acquisition outcomes. Acquired, failed, and resource-limited results publish with the refresh transaction and appear in provider inspection; reports never initiate downloads. The refresh summary also counts packages without resolved source targets. `--require-complete` changes the exit status of an incomplete source refresh after its coherent partial results publish. Interruption reaps workers, removes temporary trees, rolls back acquisition writes, and retains the previous snapshot.

The storage boundary owns a sidecar snapshot lock beside the SQLite database. Reports take the sidecar's shared lock before their SQLite read transaction and hold it through report construction. Refresh takes SQLite's writer lock first and the sidecar's exclusive lock only for retention and commit. This order lets reports read the previous snapshot during inventory capture while preventing retention from overlapping a report read. The `count` report compares its committed snapshot fingerprint with the live local inventory and reports packages without source-language profiles as missing analysis.

The `providers` report reads selected package identities and their version-matched provider attempts from the published snapshot in one SQLite read transaction. It exposes every candidate, target, evidence grade, unresolved reason, and optional recipe provenance in all four report formats, with package totals for resolved, unresolved, and not attempted. A package with any resolved candidate is counted as resolved without selecting a provider winner. Historical versions do not supply current evidence.

## Alternatives

Paclang does not link to libalpm for installed-database metadata. The available accessor is specific to a pacman fork, so it cannot provide one package-origin contract across supported ALPM systems. [ADR 0010](../docs/adr/0010-do-not-depend-on-fork-specific-origin-metadata.md) records the decision and its evidence.
